# Genesis Ceremony Protocol

**Status: DRAFT.** The ceremony tooling in `ops/genesis/ceremony.sh` is
implemented and tested; no official public-testnet or mainnet genesis has been
produced with it. The official ceremony waits on the owner-supplied founder,
treasury and bootstrap-seed `kvnc...dag` addresses (addresses only, never
private keys). Do not treat any example address in this document as canonical.

Consensus Impact: Ledger initialization; executed once before chain start.
Architecture: **Hybrid PoW + GHOSTDAG** on chains 1 and 2 (NO stake for
consensus; target block 4 s, GHOSTDAG $K=5$; PoW hash: KovanicaHash). Chains 3
(devnet) and 1337 (local) keep the legacy policy for development.

Purpose: produce, from the owner's addresses, the genesis file set every node
on a network must hold byte for byte: initial state, treasury address, founder
premine and chain ID.

| Chain ID | Network | Emission policy | Addresses |

| `1` | kovanica-mainnet (chain ID 1) | `no-stake-82m` (forced) | PRO-21 `kvnc...dag` only |
| `2` | kovanica-testnet (chain ID 2) | `no-stake-82m` (forced) | PRO-21 `kvnc...dag` only |

There is no chain ID 4 or chain ID 5. `testnet/chain4/` stays in the tree as history
and is not an input to the ceremony, an install target or a bundle source.

## 2. Inputs

- **`validators.json`** — JSON array of bootstrap seed nodes:
  `{ "address": "<canonical PRO-21 address>", "public_key": "<32-byte hex>" }`.
  The legacy `stake` field is not used: on chains 1 and 2 nothing is staked.
- **Treasury address** (`--treasury-address`, mandatory) — the address the
  treasury is initialized for.
- **Founder address** (`--founder-address`, mandatory) — receives the 200,000
  KVNC premine.
- **Chain ID** — inferred from `--network` (`mainnet` 1, `testnet` 2, `devnet`
  3, `local` 1337) or set explicitly with `--chain-id`.

On chains 1 and 2 every validator, founder and treasury address must already be
a canonical PRO-21 `kvnc...dag` address. Legacy hex is **refused**, not
converted: the ceremony never rewrites an address, derives a key from one, or
invents keys to repair a committed file.

### Tokenomics written by the ceremony

| Item | Amount | Where it lives |
|---|---|---|
| Founder premine | 200,000 KVNC | minted at first start from `founder_premine.hex` |
| Treasury allocation | 8,000,000 KVNC | allocation with 1M/year linear vesting, starting at `vested = 0` |
| Mining subsidy budget | 82,000,000 KVNC | emitted block by block by the node |
| Genesis validator allocation | 0 KVNC | nothing is minted or staked at genesis |
| **Total** | **90,200,000 KVNC** | |

The treasury is an 8M **allocation**, not an 8M genesis balance: the treasury
account holds nothing until vesting releases the first tranche. The ceremony
does not change emission or vesting math. `funded_accounts.toml` pre-funding
(on chains other than 1) is extra and is not part of this arithmetic.

## 3. Procedure (`ops/genesis/ceremony.sh`)

```bash
./ops/genesis/ceremony.sh --network testnet \
    --validators <validators.json> \
    --treasury-address <treasury-kvnc...dag> \
    --founder-address <founder-kvnc...dag> \
    --output ./genesis-out
```

Add `--chain-id <id>` to override the network default, `--force` to overwrite
files inside `--output`, and `--generate-keys` to write throwaway validator
keys under `<output>/keys` (never commit them).

Steps:

1. **Validate and write the file set.** Every address is checked before the
   node runs, so a refused input leaves no output behind. Writes
   `genesis_validators.toml` (see §4) and `founder_premine.hex`.
2. **Generate `genesis.json`.** Runs `kovanica-node genesis` with the same
   addresses and computes the staking/tokenomics preview. On chains 1 and 2 the
   script always passes `--emission-policy no-stake-82m`; the node fails closed
   without it.
3. **Key generation.** Reports the throwaway keys when `--generate-keys` was
   given; otherwise the input key configuration is untouched.
4. **Write `bootnodes.toml`** with the network seed
   (`testnet.kovanica.online:8000` or `mainnet.kovanica.online:8000`).

The default `--output` is `./genesis-out/`, which is gitignored. The script
refuses an output that would land on a committed artefact
(`testnet/genesis.json`, `testnet/node-data/genesis.json`,
`mainnet/genesis.json`, `ops/docker/validators/genesis.json`) or inside a
committed genesis/key directory (`testnet/chain4/`, `testnet/validators/`,
`ops/docker/chain2/`, `ops/docker/validators/`, `mainnet/`, `testnet/node-data/`),
even with `--force`.

## 4. Configuration formats

### 4.1 `genesis_validators.toml`

The ceremony writes kovanica-testnet (chain ID 2) as:

```toml
# Kovanica testnet genesis validators (generated by ops/genesis/ceremony.sh)
# Network: kovanica-testnet (chain ID 2)
chain_id = 2
emission_policy = "no-stake-82m"
treasury_address = "kvnc...dag"

[[validator]]
address = "kvnc...dag"
public_key = "<32-byte hex>"
```

- `chain_id` is mandatory on kovanica-mainnet (chain ID 1) and kovanica-testnet (chain ID 2) and must equal the node's
  configured chain.
- `emission_policy` must be `no-stake-82m` on kovanica-mainnet (chain ID 1) and kovanica-testnet (chain ID 2).
- There is **no `stake` field**. Under `no-stake-82m` no stake is locked at
  genesis; a legacy genesis applies `MIN_VALIDATOR_STAKE` itself.
- `treasury_address` is recorded so the bundle and the installer can bind the
  same value a node uses. `genesis-bundle` computes `expected-tag` with it and
  `node/scripts/install.sh` writes it into a new node config. The node itself
  reads only the configured address (`KOVANICA_TREASURY_ADDRESS` or
  `treasury_address` in the config), never this file.

### 4.2 `founder_premine.hex`

One line: the founder address (`kvnc...dag` on kovanica-mainnet (chain ID 1) and kovanica-testnet (chain ID 2)). `init_genesis`
mints the 200,000 KVNC premine only when this file is present in
`KOVANICA_DATA_DIR`, and `genesis_config_digest` binds the address inside it.

### 4.3 Why `genesis.json` is not state

`kovanica-node genesis` writes a preview of the staking state and allocations.
A running node does not take balances from it: `init_genesis` derives genesis
state from `genesis_validators.toml`, `founder_premine.hex`,
`funded_accounts.toml` and `KOVANICA_TREASURY_ADDRESS`. Do not distribute
`genesis.json` as if it were the state.

## 5. Bootstrap seed node bounds (kovanica-mainnet (chain ID 1) and kovanica-testnet (chain ID 2))

- No stake is required in the consensus path: blocks are mined with
  Proof-of-Work (KovanicaHash) and ordered with GHOSTDAG ($K=5$).
- kovanica-mainnet (chain ID 1) requires **1..=20** declared bootstrap seed nodes; the same bound is
  enforced as a maximum on kovanica-testnet (chain ID 2). The retired 15-validator BFT quorum floor
  does not apply.
- A lean deployment of **3–5 bootstrap seed nodes** is recommended for public
  discovery.
- `kovanica-node --check-config` enforces the mainnet bound when a ceremony
  file is present.

### 5.1 Prohibition of `funded_accounts.toml` on kovanica-mainnet (chain ID 1)

```toml
[[account]]
address = "kvnc..."
balance = 1000000000000
```

Pre-funding accounts from `funded_accounts.toml` is permitted only on kovanica-testnet (chain ID 2),
kovanica-devnet (chain ID 3) and local (chain ID 1337). On **kovanica-mainnet (chain ID 1)** the file is **strictly prohibited**: every
KVNC must originate from the published allocation (founder premine, treasury
vesting, mining subsidy), so the node aborts at startup and `genesis-bundle`
refuses to package it. The mainnet `sha256sum` list therefore omits it (see
[`docs/TESTNET-RESET.md`](TESTNET-RESET.md)).

## 6. Genesis digest guard (startup behaviour)

On first startup the node computes a cryptographic digest over the genesis
inputs (canonical block digest, chain ID, treasury address and the genesis files
in the data directory) and persists it:
- **Match:** startup proceeds.
- **Mismatch:** startup aborts with an explicit configuration error.
- **Existing chain state without a digest:** startup is refused.

Every node must therefore use the same chain ID, the same binary and the same
genesis file set, byte for byte, plus the same `KOVANICA_TREASURY_ADDRESS`.

## 7. Publishing a bundle

Cut the published archive with the node binary; never assemble it by hand:

```bash
kovanica-node genesis-bundle --chain-id 2 --source <genesis-dir> \
    --out kovanica-chain2-genesis.tar.gz
```

`--source` must contain only genesis files (`genesis_validators.toml` is
required; `founder_premine.hex`, `funded_accounts.toml` and `validators.json`
are included when present). Any other entry — a key, a keystore, a
`config.toml` — is refused. The archive is byte-for-byte deterministic and
carries `SHA256SUMS` and `expected-tag`, which is what
`node/scripts/install.sh` verifies.

The source directory for kovanica-testnet (chain ID 2) must be the output of the ceremony above
(including `founder_premine.hex`), with `chain_id = 2` in
`genesis_validators.toml`. `.github/workflows/release-node.yml` is pointed at
`testnet/chain2/`, cuts `kovanica-chain2-genesis.tar.gz` from it and fails
closed if that directory is missing. Publishing the archive still needs a
`v<version>-node` release created by ops; this repository only carries the
source file set.

**Treasury binding.** `genesis-bundle` computes `expected-tag` from the chain
id, the genesis file set and the `treasury_address` recorded in
`genesis_validators.toml`. It still ignores `KOVANICA_*` overrides, so a bundle
is reproducible from its files alone. On kovanica-mainnet (chain ID 1) and kovanica-testnet (chain ID 2) a source that does not
record a canonical PRO-21 treasury is refused before an archive is written; on
kovanica-devnet (chain ID 3) and local (chain ID 1337) an absent field keeps the zero-treasury default.
`node/scripts/install.sh` writes the recorded address into a new node config,
and refuses to keep an existing config whose effective treasury (the config
file, or `KOVANICA_TREASURY_ADDRESS`, which wins) differs from the bundle. A
node started without the installer must set the same
`KOVANICA_TREASURY_ADDRESS` or the same `treasury_address` in its config;
otherwise its digest, and therefore its tag, differs and it cannot join.

## 8. Offline ceremony for kovanica-mainnet (chain ID 1)

Before kovanica-mainnet launch (1.1.2027), Toni conducts the offline genesis ceremony in a secure, air-gapped environment.

### 8.1 Inputs Provided by Toni vs Fixed Parameters
Tooling accepts **public addresses and public keys only**; private keys and keystores are never touched, ingested, or generated by the ceremony tool (`--generate-keys` is rejected fail-closed on kovanica-mainnet):
- `--founder-address`: Toni's canonical PRO-21 address (`kvnc...dag`) for the 200,000 KVNC premine.
- `--treasury-address`: Canonical PRO-21 address (`kvnc...dag`) for the 8,000,000 KVNC treasury vesting vault.
- `--validators`: JSON file containing 1..=20 declared bootstrap seed nodes with 32-byte hex public keys and PRO-21 addresses (no stake, hybrid PoW+GHOSTDAG).
- All addresses must be canonical PRO-21 base32 (`kvnc` + 57 base32 chars + `dag`); legacy hex format is strictly rejected.

**Fixed in `kovanica-params` / consensus (not ceremony inputs):**
- **Founder premine:** 200,000 KVNC (`FOUNDER_PREMINE = 200_000 * ONE_KUNA`), minted at first start from `founder_premine.hex`.
- **Treasury vesting:** 8,000,000 KVNC total at 1,000,000 KVNC/year over 8 years (`TREASURY_TOTAL`, `TREASURY_ANNUAL`, `TREASURY_YEARS`), bound by `KOVANICA_TREASURY_ADDRESS`.
- **Initial target / difficulty ceiling:** `MAX_TARGET_BITS = 0x1f00ffff` (`crates/kovanica-params/src/lib.rs`).
- **Genesis timestamp:** Genesis time is not an input; the genesis block timestamp is 0 by protocol consensus invariant.
- **Emission policy:** `no-stake-82m` (82,000,000 KVNC mining budget, 0 genesis validator stake allocation).

### 8.2 Execution
Run the ceremony script targeting kovanica-mainnet:

```bash
ops/genesis/ceremony.sh \
    --network kovanica-mainnet \
    --founder-address <TONI_FOUNDER_PRO21_ADDRESS> \
    --treasury-address <TONI_TREASURY_PRO21_ADDRESS> \
    --validators <PATH_TO_BOOTSTRAP_SEEDS_JSON> \
    --output ./mainnet-genesis-out
```

The ceremony script verifies:
1. Emission policy is `no-stake-82m`.
2. No stake allocations are written (`genesis_validator_allocation_atoms = 0` and `genesis_validator_allocation_kovanica = 0`).
3. `funded_accounts.toml` is not generated (strictly prohibited on kovanica-mainnet).
4. Bootnodes config points to DNS endpoints only (e.g. `mainnet.kovanica.online:8000`), never raw IP addresses.
5. A cryptographic `SHA256SUMS` manifest is generated for the ceremony outputs (covering `genesis_validators.toml`, `founder_premine.hex`, `genesis.json`, and `bootnodes.toml`).

*(Note: Target block time of 4 seconds, GHOSTDAG $K=5$, and fee split of 3/4 burn and 1/4 miner are enforced directly by `kovanica-consensus` and `kovanica-params`, not checked by the ceremony script.)*

### 8.3 Verification & Safety Guard
Before committing the ceremony outputs:
1. **Placeholder check:** Ensure no `PLACEHOLDER_MAINNET_*` tokens remain. `kovanica-node` verifies files fail-closed: `genesis.json` is checked at node startup (via `verify_genesis_json` and `check_chain_id`) and `genesis_validators.toml` is checked when packaging bundles (via `genesis-bundle`). If any placeholder string `PLACEHOLDER_` remains in these files, the node halts with an error.
2. **Bundle validation:** Validate the output directory with the node binary:
   ```bash
   kovanica-node genesis-bundle --chain-id 1 --source ./mainnet-genesis-out --out kovanica-mainnet-genesis.tar.gz
   ```
3. **Checksum verification:** Confirm the SHA-256 sums match:
   ```bash
   cd ./mainnet-genesis-out && sha256sum -c SHA256SUMS
   ```

### 8.4 Commit Locations
Currently, only the template `mainnet/genesis.json` is committed in the repository (the retired legacy validator configuration was archived to `docs/archive/mainnet-legacy-81m/`). Note that `mainnet/genesis_validators.toml` does not currently exist in the repository.

Upon successful completion of the offline ceremony by Toni, the verified ceremony outputs are committed to the repository under `mainnet/`:
- `mainnet/genesis.json` (canonical genesis configuration preview)
- `mainnet/genesis_validators.toml` (declared bootstrap seeds and treasury binding; created by ceremony)
- `mainnet/founder_premine.hex` (premine payload; created by ceremony)
- `mainnet/bootnodes.toml` (DNS-only seed endpoints; created by ceremony)
- `mainnet/SHA256SUMS` (cryptographic manifest covering all 4 files; created by ceremony)

No IP addresses, keystores, or private credentials may ever be committed to the repository.

### 8.5 OPEN for Toni (Decisions & Confirmation)
The following consensus parameters and network configuration items are fixed in code (`kovanica-params` and consensus engine) or set as defaults in `ops/genesis/ceremony.sh`. Toni should review and confirm these params/consensus decisions prior to mainnet launch:
1. **Founder premine:** 200,000 KVNC (`FOUNDER_PREMINE = 200_000 * ONE_KUNA = 200_000_000_000_000` atoms) minted at first start to `--founder-address`.
2. **Treasury allocation & vesting:** 8,000,000 KVNC total (`TREASURY_TOTAL = 8_000_000 * ONE_KUNA`), vesting at 1,000,000 KVNC per year (`TREASURY_ANNUAL = 1_000_000 * ONE_KUNA`) over 8 years (`TREASURY_YEARS = 8`), bound to `--treasury-address`.
3. **Max target bits / difficulty ceiling:** `MAX_TARGET_BITS = 0x1f00ffff` (canonical production consensus ceiling in `crates/kovanica-params/src/lib.rs`).
4. **Genesis timestamp:** Genesis time is not a ceremony input; the genesis block timestamp is 0 by consensus protocol invariant.
5. **Default bootnode endpoint:** `mainnet.kovanica.online:8000` hardcoded as the default mainnet seed endpoint in `ops/genesis/ceremony.sh:319` (must resolve via grey-cloud DNS to the mainnet seeder host).

## 9. Network safety rules

- Keep seed DNS records strictly **grey-cloud** (no Cloudflare proxying or CDN).
- P2P transport operates on port **8000** (TCP + Noise + Yamux).
- Faucets are disabled on seed nodes (`FAUCET=0`).
- Mining nodes operate permissionlessly with standard PRO-21 addresses via
  `KOVANICA_MINING_AUTHOR`.
